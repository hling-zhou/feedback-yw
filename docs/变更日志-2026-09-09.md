# 变更日志 · 2026-09-09 · EIP 切换到人工基线 curated 分类法

## 一、背景与根因（为什么改）
用户指出当前行动建议模块存在系统性问题：
1. **1/2 级分类定义含糊**，归类错误、类目间重叠、类目散乱。
2. 生成的行动建议**阅读负担重、价值不高**（多为"待人工收敛"占位）。
3. 具体误吸案例：工单 `36.138.206.179`（真声"按量付费弹性IP 加入共享带宽时…几分钟后自动**回退**为原有带宽模式"）被错归到"关联资源绑定·订购·无法单独调整下行速率"。

根因：二级类目由分析过程**自动挖掘短语**生成（autoSplit），定义天然含糊、正则泛吸、与已定义类目重叠。

## 二、决策（用户拍板）
**放弃"分类由分析过程中自动生成"，改为人工预先定义一批清晰、互斥、边界明确的 curated 类目（含行动建议模板）。** 经确认：**① EIP 先试点**；**② 分类 + 建议模板一起定义**（每类配一条可交办动作，根治"空泛待人工收敛"）。

## 三、改动清单
- **新增 `scripts/eip-taxonomy-curated.json`**：17 个家族 / 42 个子议题，每个含 `rec`（标准行动建议模板）与正则。家族覆盖网络链路质量、公网连通与路由、带宽质量/容量、配额有效期/申请提升、共享带宽包、关联资源绑定、计费账单、退订释放、到期冻结、灰度权限、安全封堵、监控诊断、文档指引、开通交付、容量售罄等。
- **`scripts/validate-action-recs.cjs` 4 处改造**：
  1. IIFE 加载 curated JSON → 注入 `CAUSE_TAX_MAP['弹性公网IP'] = { curated: true, families }`；
  2. `analyze()` 中 curated 路径**跳过 autoSplit**，未命中子议题直接落家族「（其他/通用）」兜底桶；
  3. 给每个 item 挂 `recText`（子议题精确 `rec` → 家族兜底 `rec`）；
  4. `card()` 用 `recText` 替代"〔待人工收敛〕"占位。

## 七、子议题层全落"其他/通用"的根因与修复（同日追加）
用户发现报告里**每个家族章节都标着"·（其他/通用）"**，即子议题层完全没生效、2393 单全落家族兜底桶。

### 根因（两个引擎 bug）
1. **`scoreSubs` 把对象当数字相加（致命）**：`scoreSubs(i, fam, LW)`（行 1376）写成
   `const v = scoreText(...) + scoreText(...) + scoreText(...);`
   但 `scoreText` 返回的是**对象 `{s, hitN}`**（与 `scoreFamilies` 正确取 `.s` 相反）。对象相加得 `"[object Object]..."` 非数字 → `ss[0].v > 0` 恒假 → `subHit` 恒为 null → 每张工单落"其他/通用"。
   该 bug 此前被 autoSplit 掩盖（旧路径靠自动挖短语造子议题，不依赖 `scoreSubs.subHit`）；**curated 子议题全靠 `scoreSubs.subHit` 指派，缺陷才第一次被触发**。
   **修复**：改为 `scoreText(...).s + scoreText(...).s + scoreText(...).s`（与 `scoreFamilies` 对齐）。`scoreAllSubsFlat`（1401，备用）同改。
2. **`analyze` tier 指派漏特判 `crossCut`**：tier 循环只特判了 `unloc`（`tier='unloc'`），却给所有 item（含 `crossCut` 横切项）赋了 5 层 tier。修复前 VPC 的"文档与自助能力缺口"家族 2 个横切项带了 iteration/tail tier → 门禁"横切项单列"判 FAIL（29/1）。
   **修复**：`if (it.crossCut) { it.tier = 'cross'; it.highHarm = false; continue; }`（与 `unloc` 对齐，`cross` 在 TIERS5 之外，符合"横切项单列"设计）。

### 修复后结果
- EIP 具体子议题归属：**0 → 2104 单（88%）**，家族兜底从 2393 降到 289（12%）；具体子议题数 30 → 36。
- 三方门禁重跑：**30/30 PASS**（修复中曾短暂 29/1，修 crossCut 后恢复）。
- 报告 `docs/行动建议-弹性公网IP-验证.md` 已重生成，章节标题变为具体子议题（如「配额申请与提升 · 申请提升/增加配额」1706 单、「网络链路质量 · 丢包」35 单）。
- 报告头 curated 文案被 runPipeline 模板覆盖问题：将 `md()` 模板改为 curated 感知（传 `tax.curated`），写入 `validate-action-recs.cjs` 1576-1577/1703，重跑后头正确。
- 临时诊断脚本 `_diagsub.cjs` / `_diagsub2.cjs` / `_realtest.cjs` 已清理。

## 八、curated v2：泛词收窄 + 反向排除（同日追加）
用户审查后指出 42 子议题不满足「边界清晰/归类标准明确/工单无误入」三条标准，要求执行修订清单。

### 改动
- **引擎**（`validate-action-recs.cjs`）：`scoreFamilies`/`scoreSubs` 支持 `exclude` 字段——命中正向 re 后检查 exclude，命中则该家族/子议题不得分（家族级 exclude 让工单回归正确家族，子议题级 exclude 让工单落家族兜底）。

## 十、引擎机制升级：真声拼接 + 原因清洗提权 + 共现短语 + LLM辅助框架（同日追加）
用户指出三个深层问题：①真声只取一个字段不够、②问题原因权重0.3太低、③散词命中模式太机械。

### 改进1：真声清洗拼接（替代取第一个回退）
- `voiceOf` 改为拼接 `客户请求内容 + 受理内容(清洗) + 处理意见(清洗)`，去重后作为完整真声。
- 新增 `cleanFlowNoise()`：剥离客服流转句式（客户标签/请求节点/工单标题/受理渠道/客服组/协办/预处理/产品UUID/协助请求/处理意见前缀等）。

### 改进2：问题原因清洗处置结论 + 提权
- 新增 `cleanReason()`：剥离处置结论句式（已通知/已为客户/已协助/省代表通知/建议客户/请客户等开头的子句）。
- 权重 0.3→**0.7**（与痛点持平，低于真声1.0）。清洗后保留的问题陈述质量接近痛点。
- `textForMatch` 改用 `cleanReason(get(r,'问题原因'))`。

### 方向A：共现短语（子句级因果链匹配）
- 引擎新增 `scorePhrases()`：子议题/家族可定义 `phrases`（正则数组），在子句级别匹配共现模式，命中给固定加分（散词最高分×2.0）。
- `scoreFamilies`/`scoreSubs` 调用 `scorePhrases` 作为额外加分层。
- 四产品 JSON 补关键 phrases：EIP(quota_increase复合工单/netlink因果)、云专线(renew续订变更/provision新建/link_quality断连/billing折扣)、VPC(conn内网不通/diag诊断工具/peering排除配额)、ELB(cert证书替换/forward转发失败/provision订购失败/health排除转发)。
- JSON 加载处编译 `phrases` 字段。

### 方向C：LLM辅助判定框架（默认关闭）
- 新增 `scripts/llm-assist.cjs`：对复合工单（命中≥3家族或2家族且置信度<0.4）调 LLM 判定主诉归属。
- 触发：`LLM_ASSIST=1` 环境变量启用；需配置 `LLM_API_KEY`（.env 或库内 llm_config_v1）。
- `classifyScored` 返回 `assistCandidates`（复合工单列表）；emit 阶段异步批量调 LLM，记录到 `dist/llm-assist-log.json`。
- 三方分离不破坏：LLM 只判定主诉（给家族key+理由），不改分类法、不写产物、不替代散词匹配。
