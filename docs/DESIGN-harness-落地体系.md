## Ⅰ · Harness 五维体系陈述

### 0. 总纲判据

Harness 的本质：**把「AI 靠得住」从模型的临时状态，改造成系统的结构属性。**

检验任何一条保障，只问一句：**「它由什么结构保证？」** 答案是「AI 会自觉」的，等于没有保障。
可靠性必须外部化，形态只有五种（约束阶梯的雏形）：注入、触发、留痕、拦截、不可表达。

五维不是并列清单，是一个判定流程：拿到任何一条纪律/约定/保障 → 问**由什么结构保证**（总纲判据）→ 定它在**约束阶梯**的档位 → 检查它的**失效模式**与**验证维度是否对位** → 按**投资经济**决定是否上 → 有效则沉淀进**知识飞轮**、经**控制契约**在层间传递 → 下次任务从注入开始受益。

### 维度一：控制契约化（分离控制，原 harness 原则 1 的完整形态）

控制环是主线，四段：**意图对齐 → 规划设计 → 执行开发 → 验收确认**。
「分离控制」不是把规划与执行交给不同实体，而是把四段的控制权显式分账：

| 层 | 控制权归属 | 项目落点 |
|---|---|---|
| 意图对齐 | 用户独占——AI 只能复述，不能定义 | 对齐三样（01 文档 §1） |
| 规划设计 | AI 提案、用户放行 | 方案先行，改数据模型走变更管理（05 文档） |
| 执行开发 | AI 全权，按纪律 | 01/03/防缺陷触发规则 |
| 验收确认 | 用户独占——AI 只能提供证据 | 真实链路证据 + 复述确认（04 文档） |

层与层之间靠**契约**衔接，不是靠「下一个 AI 会话会想起来」：
- 契约①：对齐三样——需求是否进入执行，以用户确认为准
- 契约②：方案→开发——验收点与守卫清单在写码前确定
- 契约③：开发→交付——真实链路证据（真参数、完整链、非推演）
- 契约④：交付→复盘——复盘四层深挖标准（用户 11-06 拍板）

**反模式警示**：一个 AI 会话包干四段而无显式契约，控制权全部回流到 AI 脑内，harness 失效。

### 维度二：知识闭环化（知识反哺，原 harness 原则 2 的完整形态）

控制环交付这一次的结果，知识环让下一次更可靠。三段：
**复盘归因（四层深挖）→ 登记固化（按成本分档沉淀）→ 分发注入（回到控制环入口）**。

登记固化的成本分档（与维度五联动）：
- 高频教训 → 项目约定文档（docs/conventions/ 各主题）
- 高危+可机器断言 → 守卫测试/审计脚本（并登记 README 守卫索引）
- 跨项目通用 → 用户全局记忆（~/.workbuddy/ 用户级）
- 过程性 → .workbuddy/memory/ 日志（不入库）

**飞轮自带排出机制**：复核以代码 + 运行日志为真源；用户最新指令覆盖旧约定；守卫红灯的第一反应是质询约定而不是绕过守卫。知识只进不出会腐化。

### 维度三：约束阶梯化（把「必读」变「必到」）

五档强度，越往上越硬、越贵、越靠近失败点：

| 档位 | 机制 | 项目现状 |
|---|---|---|
| L5 结构性消除 | 类型系统、单源派生设计、key 唯一性——违规不可能发生 | 部分有（受控 Tabs 单源、类型层） |
| L4 机器拦截 | 守卫测试、审计脚本、pre-commit hook——exit 1 确定性 | 8 个守卫，无出口 hook |
| L3 触发注入 | 项目 skill、必经通道承载（AGENTS.md 正文）——出现即注入 | **断层：约定在库里等读，无推力** |
| L2 留痕复核 | 对齐三样固定回帖、锚点 grep 留痕、证据留档——执行产生可审计痕迹 | 在做，无固定格式 |
| L1 明文约定 | docs/conventions/、MEMORY.md、AGENTS.md——最低成本，也最低强制力 | 已健全 |

**阶梯下沉原则**：每条纪律应落在它能承受的最低成本档——能类型消除不写测试，能测试不注入，能注入不只留痕。「能机器断言的事靠 AI 自觉」与「只能人判的事硬写脚本」都是成本错配。

**关键转变**：11-18 拍板把执行方式从「拉模式」（AI 记得去读）升级为「全程默认」，但注入通道仍需结构保证。L3 的补法：AGENTS.md 正文直载高危纪律 + 项目 skill 封装。

### 维度四：失效对位化（纵深防御与验证维度对齐）

**1. 纵深防御**：任何一道闸门都假设它前面的闸门全部失效来设计。pre-commit hook 不假设「AI 跑过守卫」，守卫不假设「AI 读了约定」，约定不假设「记忆注入成功」。任何一条纪律的失效路径上应至少有两道独立闸门——这是项目「守卫覆盖处零违例、守卫够不着处两次返工」（11-18 吸顶三连修实证）的结构性解释。

**2. 验证维度对齐**：验证手段必须与错误类型在同一维度——esbuild 只证语法、单测只证断言、sticky 是纯视觉行为需真机。每类错误的「在场验证手段」要显式列出；缺位的叫**验证盲区**，盲区里只能靠人。诚实盘点盲区是 harness 设计的输入，不是可选动作。

**3. 失效模式优先设计**：先问「它什么时候不工作」再问「它怎么工作」。守卫测试自身会腐（守卫必须红绿证明，11-04 教训）、注入通道会漏（新会话没读到记忆）、skill 会过拟合（通用方法论盖过项目拍板）。

### 维度五：投资经济化（约束成本要校准）

**1. 触发成本要入账**：每道闸门都给正常路径加税（hook 拖慢 commit、回帖模板拖慢交付）。判定标准：闸门税 < 它拦截的失效的期望损失。

**2. 约束密度与失影响力成正比**：高频路径要轻（如更新动态只收 feat/fix——每条 commit 都要走，判定必须一行能答）；低频高危路径可以重（数据模型级变更走全消费方清单+迁移方案+真实链路证据全套）。不搞一刀切。

**3. 淘汰机制**：知识只进不出会腐化。既有排出机制见维度二；harness 层面补充：守卫拦截的若是「实际想要的行为」，红灯是信号不是障碍——先质询约定再决定动不动守卫。

### 本项目现状短版诊断（2026-11-19）

- **成熟区**：L4/L5（8 个守卫+类型层+打标闸门）与知识飞轮（复盘→约定→守卫，多次实证）已跑通。
- **半缺位**：L3 触发注入——约定在 docs/conventions/ 等读，无自动推力；AGENTS.md 只有发现入口。
- **靠习惯**：L2 留痕在执行但无固定格式，无结构保证。
- **契约④有实践、无模板**：复盘四层标准在全局记忆里，未入库模板化。

## Ⅱ · 跨项目迁移指南：哪些能力可迁移

按「迁移成本 / 依赖项目特有知识程度」分三档。判定依据：能力依赖的载体是否项目特有。

### A 档：零成本直接迁移（载体是通用机制，内容可换）

| 能力 | 载体 | 迁移动作 |
|---|---|---|
| 对齐三样（复述/做什么/假设边界） | 工作方式，无代码载体 | 新项目直接沿用 |
| commit-hygiene（不自动提交、单意图、具名路径、HEREDOC） | 全局用户记忆 + 02 文档 | 已是全局约定，天然随行 |
| 真实链路验证纪律（fixture 会继承实现的心智模型） | 全局记忆 + 04 文档 | 已是全局约定 |
| 知识闭环骨架（复盘→登记→分发） | 目录结构 + 工作方式 | 复制 docs/conventions/ 骨架：README 索引 + 主题文档分档 |
| 五维判定流程本身 | 本文 | 复制本文档，替换「项目现状」列 |

**说明**：A 档能力的共同点——保障的是「AI 的工作方式」而不是「这个项目的代码」。工作方式层面的约定随会话注入迁移，零代码成本。

### B 档：低成本移植（骨架可复制，内容需按新项目重写）

| 能力 | 载体 | 迁移动作 |
|---|---+---|---|
| docs/conventions/ 目录模式 | README 索引 + 8 份主题文档 | 复制结构（索引/分档登记/守卫登记表），内容按新项目重写 |
| 守卫测试模式（守卫清单 + 红绿证明） | vitest 测试文件 | **复制的是方法论**：守卫拦什么 → 红绿证明 → README 登记。具体断言必须重写 |
| 防缺陷触发规则（「做 X 时必答 Y」） | 独立文档 | 骨架可复制；条目分两半——通用条目随行（写删除必答谁持有键、计数必答何时归零），项目特有条目留下 |
| MEMORY 三层结构 | .workbuddy/ 目录 | 目录方案随行；内容按新项目重建 |
| 复盘登记落点规则（01 文档 §7） | 文档规则 | 直接沿用 |
登记入 README（新增守卫必须登记）| README 约定 | 直接沿用 |

### C 档：不可直接迁移（强绑定本项目数据/代码）

| 能力 | 为什么不可迁移 |
|---|---|
| 8 个守卫测试的具体断言 | 断言锚定本项目文件路径、组件结构、CSS 类名 |
| 03 数据口径、05 拍板清单 | 锚定本项目的数据模型与业务决策 |
| Edit 锚点回写、串行 Edit | **例外——看似项目条目，实为工具层教训**，已在全局记忆，已随行 |
| AGENTS.md 发现入口 | 项目特有目录结构 |

**迁移判定口诀**：保障的是**工作方式** → 随行（A）；保障的是**模式** → 复制骨架重写内容（B）；保障的是**本项目事实** → 留下（C）。

### 迁移操作顺序（新项目第一天）

1. 复制 docs/conventions/ 骨架（README + 主题文档空壳）；
2. 写新项目 AGENTS.md，正文直载 A 档能力 + 指向 conventions；
3. .workbuddy/memory/ 重建（全局记忆自动注入部分随行）；
4. 首次踩坑发生时按维度二成本分档登记——**不要预先凭空造约定**，约定跟着踩坑走（飞轮排出机制的另一面：没有现实输入的约定是猜测）。

## Ⅲ · 本项目补齐实施计划（待拍板）

优先级按「结构收益 / 实施成本」定，与五维诊断对应。全部为一次性建设，非持续动作。

### P0 · AGENTS.md 正文注入高危纪律（补 L3 断层，成本：改 1 个文件）

**问题**：AGENTS.md 是唯一 100% 注入所有会话的通道，目前只放发现入口——「必读」≠「必到」。
**做法**：正文直载三条最高频违例纪律（11-18/19 复盘实证的违例集中点）：
1. 同文件多处 Edit 必须串行分条消息发，禁止并行（10-25 竞态实测）；
2. Edit 锚点落盘后立即 grep 锚点名复核（11-09 单日三次同型失误）；
3. UI 结构类改动先找同页/同类先例抄，纯视觉改动（sticky/间距）必须真机验收（11-18 吸顶三连修）。
**验收**：新会话注入内容含三条纪律原文；AI 违例率下降（观察项，不设硬指标）。
**注意**：三条纪律正文与 01 文档存在重复——AGENTS.md 是「摘要层」只放最高危条目，01 文档仍是真源；正文标注「详单见 docs/conventions/01」。

### P1 · 项目级 harness skill 封装（补 L3 断层，成本：半天）

**问题**：约定靠 AI「记得去读」；dev-expert 等通用 skill 的方法论需要项目纪律框架约束。
**做法**：`.workbuddy/skills/` 下新建项目 skill（如 `project-conventions`），内容：
- 触发条件：开发类任务（需求理解/排查 → 方案 → 开发 → 测试 → commit 全周期）；
- SKILL.md 索引 docs/conventions/ 各主题 + 按任务阶段的读取路由（写 UI 前→页面UI规范；动数据模型前→05；提交前→02）；
- 对齐三样回帖模板 + 留痕要求（复述/做什么/假设边界/证据形态）。
**验收**：新会话做开发任务时 skill 自动加载（可抽查验证注入内容）；对齐三样回帖出现固定格式。
**注意**：skill 内容是「路由 + 摘要」，真源仍在 conventions/——避免双真源漂移，skill 里只写「什么时候读什么」，不复制纪律正文。

### P2 · 出口闸门：pre-commit hook（补 L4 断层，成本：半天）

**问题**：守卫是「约定要跑」，不是「必须过」——AI 或人漏跑时无兜底。
**做法**：
- `.git/hooks/pre-commit` 或 husky：只跑**受影响子集**——按 staged 文件名映射到守卫测试文件（改 src/lib/* → uiConventionsGuard 等；改 server/* → 对应 server 守卫）+ 触碰文件 typecheck 零新增；
- 全量套件不在 hook 跑（投资经济维度：hook 税收在正常 commit 上，受影响子集足够拦高频违例；全量留给 CI/发布时点）；
- 用户手动 commit 习惯适合 hook 形态；先本地后 CI。
**验收**：故意引入一条违例（如 p-6 自包）→ commit 被拦；修正后 commit 通过。红绿证明。
**注意**：vitest 临时 config 真源 = `git show e51ddce:vitest.tmp.config.mjs`，hook 内恢复逻辑要照抄；沙箱三要素约定照抄（非沙箱/env -u NODE_OPTIONS/npmmirror——hook 由 git 触发，绕过 WorkBuddy 环境，NODE_OPTIONS 坑会直接打到 hook 上）。

### P3 · 留痕模板固化（补 L2，成本：1 小时）

**问题**：对齐三样、证据留档在执行但无固定格式，「执行没执行」不可审计。
**做法**：在 01 文档补一节「交付留痕模板」：
- 开工回帖模板：复述 / 具体做什么 / 假设与不做边界；
- 交付回帖模板：改了什么（文件级）/ 验证证据（测试数字 + 真实链路证据形态）/ 已知风险与未做 / 真机确认状态。
**验收**：后续任务回帖出现可辨认的模板结构。
**注意**：模板是「必含要素」不是「必填表格」——机械填表会退化成形式合规，要素齐即可。

### P4 · 复盘四层标准入库（补契约④，成本：1 小时）

**问题**：复盘四层深挖标准（11-06 用户拍板）只在全局记忆，其他协作者与部分新会话看不到。
**做法**：在 01 文档（或新 07-复盘标准.md）登记四层标准摘要 + 指向全局 skill deep-retrospective。
**验收**：入库后新协作者可发现。
**注意**：全局 skill 承载方法论详单，项目文档只登记「本项目执行方式」——继续两层结构。

### 实施顺序与依赖

```
P0（独立，立即可做）
P1（独立，可与 P0 并行）
P2（依赖 P0/P1 完成后评估 hook 范围更稳）
P3、P4（独立文档改动，随时可做）
```

**预计总投入**：约 2 天内完成全部（P0 一小时级 / P1 半天 / P2 半天 / P3+P4 两小时）。

### 执行原则（来自五维体系）

- **阶梯下沉**：P0/P1 是 L3 注入，P2 是 L4 拦截，P3 是 L2 瘦身, P4 是契约④入库——不做 L5 级重投资（当前无此需要）。
- **不造未来约定**：全部条目来自已发生违例/复盘，无凭空预建。
- **每次实施后按 01 §7 复盘登记落点**。
- **成本入账**：P2 hook 税（每次 commit 增加几十秒）< 拦截的失效期望损失（守卫漏跑导致部署炸——11-11 实证过一次）。

## Ⅳ · As-built 全景：本项目 harness 工程体系（2026-11-19 21:30 落地后）

> 本章是体系的**速查入口**：一屏看全「一条任务从进会话到 commit，每一步由什么结构保证」。
> 各机制的真源在其所指文档；本章只做索引与运行时视角串讲，不复制正文。

### 4.1 一条开发任务流经的闸门链（运行时视角）

```
会话启动
  ├─ L3 注入层（不依赖 AI 记得）：
  │   ① AGENTS.md 全文注入 —— 正文直载三条高危纪律（串行 Edit / 锚点 grep 复核 / UI 抄先例+纯视觉真机）
  │   ② 项目长期记忆自动注入（MEMORY.md 执行纪律区）
  │   ③ 项目 skill「project-conventions」—— 开发类任务触发即载入约定路由表
  ↓
开工
  └─ L2 留痕层（01 §1 + §6.1 模板）：
      对齐三样回帖：复述需求 / 具体做什么 / 假设与不做边界 → 用户确认才进执行
  ↓
执行（按 skill 路由表读约定）
  ├─ 排查纪律（01 §5）：先探服务在不在 / dump 数据形态 / 禁循环论证 / 解释必能被查询指认
  ├─ 防缺陷触发规则：「做 X 时必答 Y」11 条
  └─ 留痕：锚点 Edit 落盘即 grep 复核；同文件串行分条发
  ↓
交付（01 §6.1 交付模板）
  └─ 改动清单 + 验证证据（受影响 vitest 子集数字 + 真实链路证据）+ 真机确认状态显式声明
  ↓
commit（02 commit-hygiene + L4 出口闸门）
  └─ .git/hooks/pre-commit：
      staged 文件 → 守卫子集映射（6 全域守卫 / chrome.render / catalogCache）
      + typecheck 拦 staged 新增 TS2304/2307/2552
      违例 → exit 1 拦截；HARNESS_SKIP_PRE_COMMIT 逃生变量
  ↓
复盘（01 §6.2 四层标准 + deep-retrospective skill）
  └─ 四层深挖 → 三层防复发落点登记（记忆 / 守卫+README 登记 / conventions 文档）→ 回到注入层
```

### 4.2 机制清单（as-built）

| 层 | 机制 | 载体 | 强制力 |
|---|---|---|---|
| L1 | 约定真源库 | `docs/conventions/`（README 索引 + 8 主题文档） | 明文，人+AI 共读 |
| L2 | 交付留痕模板 | 01 §6.1（开工/交付回帖必含要素） | 痕迹可审计 |
| L2 | 复盘四层标准 | 01 §6.2 + 全局 deep-retrospective skill | 标准强制 |

| L3 | 项目 skill | `.workbuddy/skills/project-conventions/`（路由层，不复制正文） | 开发任务触发即载入 |
| L3 | 项目记忆 | `.workbuddy/memory/`（MEMORY.md + 日志，不入库） | 每会话自动注入 |

### 4.3 已知边界（诚实盘点，对应维度四）

- **hook 不随克隆迁移**：`.git/hooks/` 本地目录不入 git——换机/他人克隆需重装（husky 入库可解，待拍板）。
- **真机视觉验收仍是人闸**：hook 与守卫都够不着 sticky/间距类纯视觉行为——依赖 L3 注入的三条纪律 + 交付模板显式声明「需真机确认」。
- **复述质量、业务假设完备性**：机器不可判，用户验收是最后一道闸（控制契约：意图对齐与验收确认的控制权在用户）。
- **审计脚本未接 CI**：按 README 口径，未接入必经流程的不算自动拦截。

### 4.4 维护规则

1. **新增守卫**：登记 `docs/conventions/README.md` 索引表 + 在 pre-commit hook 的 `run_guard_subset` 映射表追加行（hook 注释已写明）。
2. **新增高危纪律**（违例集中爆发时）：AGENTS.md 摘要层与 01 真源同步——摘要层只放最高频违例条目，避免膨胀稀释注入注意力。
3. **hook 自身改动**：按守卫同级对待——改完必须红绿证明（红=违例探针被拦，绿=干净文件放行），本文件 §4.1 流程走一遍。
4. **本文档与现实的偏差**：以代码 + 运行日志为真源（README 维护约定 §3）；本文描述过时时以现实为准并应回改本文。
