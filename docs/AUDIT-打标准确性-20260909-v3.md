## 五、总结与建议

### 相比 v2 的修正

| v2 结论 | v3 结论 | 原因 |
|---------|---------|------|
| "requestScene 93% 为空" → P0 | requestScene 100% 填充 | **假阳性**，导入 bug |
| "problemType 115 条误标" → P0 | problemType 130 条误标 → P1 | 数量相近，确认 |
| "优化建议模板化" → P1 | 需保留（在投诉工单子集分析中确认），但全量统计无法自动检测 | — |

### 真实问题（修正后）

1. **P0：requestScene vs problemType 系统性不一致（349 条）**  
   客户的配额申请工单，requestScene 被标为"报障与排错"但 problemType 正确标为"配额与权限申请"。根源在生产系统的自动打标逻辑——配额工单中"无法创建/订购失败"等措辞触发了报障场景判断。

2. **P1：problemType 配额→可用性误标（130 条）**  
   已在本地代码修复（`problemTypeClassifier.js` + `QUOTA_CONTEXT_RE`），但此数据从生产导出时已带此标签，需要确认生产环境是否需要同步修复。

3. **P2：零星不一致（~40 条）**  
   安全组/咨询/操作类场景与问题类型不完全匹配，规模较小。
