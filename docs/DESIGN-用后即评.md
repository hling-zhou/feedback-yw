# 用后即评功能设计说明

> 状态：**已实现（生产）**。  
> 读者：产品 / 分析 / 研发。本文是用后即评的功能、分析内容与数据口径说明。  
> 分析规则版本：`pur-insight-v1`；原因规则版本：`pur-reason-v2`。  
> 操作入口见 [USER-GUIDE.md](./USER-GUIDE.md)。月报交付细则见 [POST-USE-ONLINE-TO-WORD.md](./POST-USE-ONLINE-TO-WORD.md)。投诉回访补全工单见 [DESIGN-用后即评-满意度回访.md](./DESIGN-用后即评-满意度回访.md)。

---

## 1. 模块定位

用后即评把「用完产品后客户怎么评」做成可分析、可下钻、可对外交付的闭环：导入短信与官网问卷、补投诉回访与客服部回访，在工作台给出周期结论，再按月输出 HTML 月报。

它服务三件事：

| 读者要的结果 | 系统提供 |
| --- | --- |
| 这个周期体验怎样、问题在哪 | 洞察工作台「用后即评」Tab：故事页 + 证据下钻 |
| 这个月对外怎么讲 | 独立 HTML 月报（可编辑叙述、可导出离线文件） |
| 该回访谁、该立什么项 | 建议回访清单、举措推荐、效果验证、用后即评 JIRA |

### 1.1 两层不要合成一层

| 层 | 角色 | 入口 |
| --- | --- | --- |
| **线上综合分析** | 权威分析层。任意洞察周期内看证据、下钻、建举措。 | `/workbench?tab=post_use_rating` |
| **HTML 月报** | 单月对外交付稿。表格锁定，总判断 / 问题结论 / 要办可编。 | `/workbench/post-use-report/:month` |

月报**禁止另写指标**。计算链路只有一条：

`故事模型 → 月报预览模型 → HTML 报告页 + 叙述覆盖层`

### 1.2 与工单分析的硬边界

| 事项 | 约定 |
| --- | --- |
| 工单批量 LLM 打标 | **不走**。用后即评非 10 分只补规则关键词「用户旅程」 |
| 反馈库通道 | 工单与用后即评分列；投诉回访独立行不出现在「用后即评满意度」列表 |
| 分析产品范围 | 只取产品目录中开启 `analysisPostUseRating` 的产品；原始导入完整保留 |
| 请求场景 / 问题类型 / 情绪 | 用后即评**不新增**这三类标签；场景用原始评价场景，旅程未知显示「未识别环节」 |

## 2. 支持的功能

### 2.1 功能地图

```text
数据导入
  ├─ 双文件渠道导入（短信 + 官网：评分类 / 选项类 / 投诉处理-电话回访）
  ├─ 客服部回访导入（visit_records，软匹配到评价明细）
  └─ 反馈库：按工单号临时复原客户名称/编码（同时可匹配用后即评 originalTicketId）
        ↓
反馈库
  ├─ 用后即评满意度：短信 / 官网评分类（不含投诉回访独立行）
  ├─ 投诉咨询工单：回访满意度列（由投诉回访双写补全）
  └─ 客服部回访：visit_records 列表
        ↓
配置
  ├─ 产品与规格：analysisPostUseRating / focusTracked
  └─ 对象与标签 → 重点客户名单（建议回访匹配）
        ↓
洞察工作台 · 用后即评
  ├─ 综合结论 / 体验现状 / 趋势与变化 / 原因与需求
  ├─ 客户与证据 / 建议回访 / 行动 / 效果验证 / 分析附录
  └─ 单月：「打开月报」
        ↓
HTML 月报（无侧栏）
  ├─ 本月判断 → 问题与证据 → 本月要办 → 附录
  ├─ 保存叙述（需 editRecord）
  └─ 导出离线 HTML / 浏览器打印
        ↓
举措与进展
  ├─ 产品举措（工作台一键创建，linkedDataSources=post_use_rating）
  └─ 用后即评 JIRA（建议回访决策跟踪）
```

### 2.2 入口与权限

无单独的用后即评权限码，沿用全局 RBAC。

| 能力 | 角色 | 触点 |
| --- | --- | --- |
| 查看 | 已登录 | 工作台、月报、反馈库 |
| 导入 | admin / editor | `/import` |
| 保存月报叙述、改 JIRA | admin / editor / partial_editor（`editRecord`） | HTML 月报、用后即评 JIRA |
| 导出 | 除 none 外 | 反馈库、建议回访 Excel、离线 HTML |
| 产品开关 / 重点客户 | admin / editor（`manageTags`） | 产品与规格、重点客户 |

`partial_editor` / `viewer` 看不到数据导入页。

### 2.3 页面清单

| 路由 | 说明 |
| --- | --- |
| `/workbench?tab=post_use_rating` | 线上综合分析故事页 |
| `/workbench/post-use-report/:YYYY-MM` | HTML 月报，挂在登录与 Insights 下，**不走 AppShell 侧栏** |
| `/import?source=post_use_rating` | 双文件 / 客服部回访 |
| `/feedbacks?lane=post_use` | 用后即评满意度 |
| `/feedbacks?lane=customer_visits` | 客服部回访 |
| `/feedbacks`（默认工单） | 回访满意度列与筛选 |
| `/tags?tab=products` | `analysisPostUseRating` / `focusTracked` |
| `/tags?tab=key_customers` | 建议回访重点客户名单 |
| `/actions?tab=post-use-jira` | 用后即评 JIRA |
| `/topics` | 专题分析 Demo，证据可含 `post_use_rating` |

## 3. 数据来源与导入

### 3.1 三类不要混名

| 名称 | 存储 | 是否进评分 | 作用 |
| --- | --- | --- | --- |
| **短信 / 官网评分类** | `post_use_rating`，`channel=sms` / `console` | 是 | 体验均分、反馈库列表、建议回访 |
| **官网选项类** | `post_use_rating`，`channel=option` | **否**（不当评分样本） | 原因证据；可触发建议回访 |
| **投诉回访** | `post_use_rating`，`channel=callback`，并双写工单 `followUpSatisfaction` | 是（满意度与对外混算） | 10 分满意率；反馈库**不展示**独立行 |
| **客服部回访** | `visit_records`，软匹配到短信/官网明细的 `customerVisit` | **否** | 补充证据与内部评估，不改均分 |

「满意度回访」在实现上就是投诉回访补到工单上的那份 `followUpSatisfaction`。独立「仅回访 Excel」导入路径仍保留代码，当前导入页下拉**只提供**双文件与客服部回访；投诉回访以官网文件里的「投诉处理-电话回访」表为主路径。

### 3.2 双文件渠道导入

入口：数据导入 → 用后即评 → **双文件**。占用全局导入锁。

| 文件 | Sheet | 纳入条件 | 关键列 |
| --- | --- | --- | --- |
| 短信渠道 | `短信渠道用后即评明细数据`（表头约第 3 行） | `调研结果状态=客户已反馈`，且有有效得分 | 产品名称、得分（加权）/得分、集团客户名称/编码、客户回复时间、整体补充评价、问卷场景 |
| 官网渠道 | `评分类` | 有效得分 | 产品名、得分、客户、填答时间、客户回答、不满原因、一级场景 |
| 官网渠道 | `选项类` | 全量保留；仅当题型含「评分」才记分 | 产品/客户/时间；原因来自客户回答等列 |
| 官网渠道 | `投诉处理-电话回访` | `是否回访成功`，且有有效评分 | 具体投诉产品、回访/原工单编号、整体服务评价、电话回访意见、各维不满意原因 |

文件名可带密码：`name#password.xlsx`。短信、官网各最多 5 个文件。

导入步骤：

1. 解析并合并。评分行按 `产品 + 得分 + 客户编码 + 填答时间` 去重。
2. 全部渠道写入 `post_use_rating`（`sourceSubType`：`sms_survey` / `web_survey` / `web_option` / `satisfaction_callback`）。
3. 投诉回访行再按原工单号补全投诉/咨询工单的 `followUpSatisfaction`。
4. 写入该月趋势快照、数据质量快照，重建对应月份洞察快照。
5. **同月重导**：先删该月已有用后即评行再全量替换。

### 3.3 客服部回访导入

入口：数据导入 → 用后即评 → **客服部回访导入**。不触发打标。

| 列 | 用途 |
| --- | --- |
| 数据月份 | 分析月份（`importMonth`）；历史无该列时兼容 `visitMonth` |
| 产品名称、客户名称/编码 | 软匹配评价明细 |
| 回访结果 | 客户侧回访反馈 |
| 内部评估 | 须落在下列 6 项之一 |

内部评估枚举：

- 无需优改（客户误操作/无实际不满/账户异常/极小概率场景）
- 综合评估后暂不处理
- 受限于移动云统一规则无法支持
- 需求接纳（依赖集团排期）
- 无需优化（其他产品问题）
- 待客户反馈

线上分析与月报按**导入所选数据月份**跟随当前范围；月报与报告月相同，不再前移一个月。

### 3.4 投诉回访补全工单

双文件导入时，回访成功且匹配到原工单的行写入工单 `followUpSatisfaction`（幂等键：回访工单编号）。规则详见 [DESIGN-用后即评-满意度回访.md](./DESIGN-用后即评-满意度回访.md)。要点：

- 同一原工单多次回访按业务约定不存在；不同回访工单号覆盖同一原工单时以最后一次导入为准。
- 反馈库工单列表展示 `10（已解决）` / `7（未解决）` / `—`，可按有无回访、10 分/非 10 分、已解决/未解决筛选。

## 4. 产品范围与配置

### 4.1 分析范围开关

在 **对象与标签 → 产品与规格** 配置。原始导入不按此过滤；工作台、月报、建议回访只看开启分析的产品。

| 标志 | 含义 |
| --- | --- |
| `analysisPostUseRating` | 纳入用后即评分析 |
| `focusTracked` | 重点跟踪产品（仅当已开分析时有效），用于趋势图默认关注 |

默认云网 16 款（种子目录，实际以当前生效目录为准）：

域名注册、共享带宽、云端口、弹性公网IP、SSL VPN、VPC终端节点、弹性负载均衡、IPSec VPN、安全组、虚拟私有云、对等连接、云互联、云组网、云专线、云监控、NAT网关。

默认重点跟踪 5 款：共享带宽、弹性公网IP、弹性负载均衡、虚拟私有云、云专线。

匹配顺序：产品 key → 标准名 → 规格名 / 别名，再规范成目录标准名。目录为空或过滤结果为空时回退到上述种子名单。

### 4.2 重点客户

**对象与标签 → 重点客户**：字符串名单，双向包含匹配客户名称。用于：

- 建议回访（低于 7 分且为重点客户）
- 高频低分原因表中的客户标识

不参与均分计算。

## 5. 反馈库行为

| 通道 | URL | 展示 |
| --- | --- | --- |
| 投诉咨询工单 | `lane=tickets` | 投诉/咨询工单；含回访满意度列；**不含** `post_use_rating` |
| 用后即评满意度 | `lane=post_use` | `post_use_rating` 且不是投诉回访独立行 |
| 客服部回访 | `lane=customer_visits` | `visit_records`，不是反馈记录 |

用后即评详情分区为「评价内容 / 评价分析 / 评价分类」。非 10 分可规则补用户旅程（`enrichPostUseJourney`），不走工单批量重打标。列表支持旅程补全，不提供工单侧批量打标 / 投诉原因人审。

## 6. 线上综合分析

工作台「用后即评」Tab 渲染 `PostUseStoryView`。周期内若无评分明细、但工单上有回访满意度，Tab 仍可有内容。

### 6.1 综合结论

四张卡片，由故事模型根据产品状态与行动缺口生成：

| 卡片 | 含义 |
| --- | --- |
| 整体状态 | 任一产品「重点改善」→ 存在重点改善产品；否则有「持续观察」→ 整体稳定仍需观察；否则整体体验良好 |
| 首要风险 | 优先点名重点改善产品 / 投诉回访不达标 / 极低分 |
| 主要变化 | 相对上一有数据月份的新增 / 增长问题 |
| 行动状态 | 本周期建议举措、已完成未恢复 |

### 6.2 体验现状

- KPI：云网均分、样本量、9 分以下产品数、投诉回访不达标产品数（对外混算 + 投诉回访 10 分率）。
- 产品体验总览表：样本、均分、非 10 分、状态、回访证据数。
- 可展开评分分布（非 10 分产品 × 1–10 分档）。

产品状态（先匹配先生效）：

| 状态 | 条件 |
| --- | --- |
| 样本不足 | `n < 10` 且没有 ≤3 分 |
| 重点改善 | 出现 ≤3 分，**或** 均分 &lt; 9，**或** 非 10 分占比 ≥ 30% |
| 持续观察 | 均分 &lt; 9.5，**或** 存在非 10 分 |
| 良好 | 其余 |

排序：重点改善 → 持续观察 → 样本不足 → 良好，再按均分升序。

### 6.3 趋势与变化

- 重点产品体验均分趋势（关注线 **9 分**）。
- 重点产品投诉回访满意度趋势（达标线 **88%**）。
- 问题变化表：按「产品 + 原因标签」比较当前月与之前最近一个有数据月。

| 变化 | 条件 |
| --- | --- |
| 新增 | 上期 0、本期 &gt; 0 |
| 消失 | 上期 &gt; 0、本期 0 |
| 增长 | 两期都 &gt; 0 且本期更大 |
| 缓解 | 两期都 &gt; 0 且本期更小 |
| 持续 | 两期计数相同 |

问题变化使用「截止当前周期结束日」的全量月份，**禁止引用未来月**。趋势图：月/季/年看自然年（锚点年到结束月）；自定义周期看所选月份。

### 6.4 原因与用户需求

- **评价触发场景 × 用户旅程**：产品 ×（原始场景，缺省「未提供」）×（旅程 L1，缺省「未识别环节」）；看样本量、均分、非 10 分数。
- **用户需求改善优先级**：从非 10 分且命中固定原因清单的文本聚合。一条原话可命中多个标签，证据 ID 相同。未命中清单的不进需求表，记入数据质量「未归类」。

优先级分：`反馈次数×4 + 客户数×3 + 严重度×2`，严重度 = 平均 `(10 − 得分)`。P0 ≥ 20，P1 ≥ 10，其余 P2。

### 6.5 客户与证据

- 客户表：非 10 分客户、涉及产品、最近原话、客服部回访结论。同一客户非 10 分 ≥ 2 次标「高频低分」。
- 高频低分原因：仅 **官网评分类**、得分 **&lt; 7**；按原因频次取 Top 5，或命中重点客户则保留。
- **建议回访 / 溯源清单**：官网评分类或选项类 + 分析范围内产品，且满足任一路径：
  - 实质负面反馈原因（不看分数、不要求重点/高频）
  - 得分 &lt; 7 **且**（重点客户 **或** 同一客户低分 ≥ 2 次）
- 投诉回访非 10 分登记：callback 渠道非 10 分，可关联原工单。清单可导出 Excel，并在用后即评 JIRA 里记决策。

### 6.6 行动与效果验证

行动信号（可一键创建举措，关联产品、主题、证据；同一洞察不重复建）：

| 类型 | 触发 | 优先级 |
| --- | --- | --- |
| 聚合需求 | 需求 P0 / P1 | 同需求 |
| 投诉回访不达标 | callback `n ≥ 10` 且 10 分率 &lt; 88% | P0 |
| 体验低于关注线 | 短信+控制台 `n ≥ 10` 且均分 &lt; 9 | P1 |
| 小样本极低分 | `n < 10` 但出现 ≤3 分 | P0 |
| 投诉回访非 10 分 | 有实质不满原因 | P0 |

效果验证只看状态为「已完成」的举措：把立项时的触发指标与**当前同口径**产品对内体验均分比较。未达到目标进入「已完成未恢复」，工作台单列并提示复盘。

### 6.7 分析附录

数据质量快照（按导入月）：原始行、解析拒绝、去重、范围内/外、无效分、缺产品、缺场景、未归类需求、投诉回访匹配/未匹配；并带目录哈希、分析规则、原因规则版本。异常可下载 CSV。

单月时工具栏提供 **打开月报**（新标签）。登录 token 在 `sessionStorage`，新标签须继承当前会话，**不必再登录**。外发或离线阅读用「导出离线 HTML」，不依赖登录。

## 7. HTML 月报

### 7.1 打开条件

- URL 月份须为 `YYYY-MM`。非法月份或当月无评分：页内说明，不生成空稿。
- 在线月报挂在登录之下，要读库、可保存叙述。工作台已登录时，新标签沿用当前会话，不必再登一次。
- 权限与工作台相同；**保存叙述**需要 `editRecord`。导出离线 HTML 凡能打开月报即可；离线文件本身无需登录。

### 7.2 文档结构

读者连续读完三件事：现在怎样、问题在哪、这个月干什么。

1. **本月判断**（不可整章隐藏）  
   KPI（云网均分，并标注相对公司均分高低、相对上月环比；样本量、9 分以下产品数、投诉回访不达标产品数）；评分分布 / 客户声音 / 产品均分 / 高频原因 / 趋势（在线可交互）；正负原话对照（可下钻反馈库）；可编辑总判断（首次用故事模型结论打草稿）。
2. **问题与证据**（最多 8 条，其余进附录）  
   排序：重点改善 → 持续观察 → 问题增长 → 待推动举措。每条：状态标签、可编结论、锁定证据（均分相对 9 分、非 10 分、问题变化、最多 3 条负向原话、同产品正反馈、回访证据数）、可编建议动作。
3. **本月要办**  
   本月提出 / 关闭的举措、已完成未恢复、建议回访摘要；可编备注。
4. **附录**（默认折叠；打印默认不带，除非勾选「打印附录」）  
   整体得分表、评分分布、场景 × 旅程、需求全表、客户与回访明细、原因聚合、有效客户原话登记。

覆盖层只存叙述与章节显隐，不写表格数字。再打开时现算表格再套覆盖层；数据指纹变化时提示「表格已按最新数据刷新，叙述仍是上次保存」。

### 7.3 离线 HTML

工具栏 **导出离线 HTML** 把**当前画面**（含未保存叙述）打成自包含文件 `用后即评月报-YYYY-MM.html`：内联 CSS、SVG 图、原生折叠附录，无外部脚本、无需登录。离线稿是锁定快照，不能再编辑保存。需要纸质/PDF 时用浏览器打印。

系统**不再**把生成/回导 Word 作为主路径。

## 8. 数据口径

以下为线上与月报共用口径。实现常量在 `src/lib/postUseRating/metrics.js`。

### 8.1 样本怎么进、怎么出

| 规则 | 口径 |
| --- | --- |
| 时间 | 洞察周期按记录 `importMonth` / `createdAt` 过滤，不以 `insightPeriodId` 为准 |
| 产品 | 解析到 `analysisPostUseRating` 产品；范围外保留在库、不进分析 |
| 评分样本 | `dataSourceType=post_use_rating` 且 `ratingScore` 为有限数字 |
| 选项类 | **排除**出所有均分 / 10 分率 / 产品状态 |
| 小样本 | `n < 10`。月报投诉回访：小样本且 10 分率 &lt; 88% 标「参考」，不算「未达标」 |
| 极低分覆盖 | 任一得分 ≤ **3** 时，即使 `n < 10` 也不按「仅供参考」放过，进入重点改善 / P0 |

短信纳入：调研结果状态为「客户已反馈」。投诉回访纳入：是否回访成功。

### 8.2 三套指标

均分：`round2(Σscore / n)`，保留两位。10 分率先算 `tenCount / n`，展示为百分数再 `round2`。

| 口径 | 渠道 | 产品 | 公式 | 用途 |
| --- | --- | --- | --- | --- |
| **对内体验** | 短信 + 官网评分类 | 云网分析产品 | 记录级均分 | 产品状态、体验低于 9 分、举措恢复对照 |
| **对内满意度** | 仅投诉回访 | 云网分析产品 | `score===10` 条数 / 有评分回访成功条数 | 88% 达标、不达标产品数 |
| **对外混算** | 短信 + 评分类 + 投诉回访 | 云网 + 公司级 | 云网：记录级均分；公司级：先按主子产品合并再均分 | 工作台分列云网/公司均分；月报「云网均分」卡片下展示相对公司均分高低、相对上月环比 |

公司级主子产品合并示例：`云主机 ECS` → `云主机`，`云电脑（办公型）` → `云电脑`（完整表见 `SUB_PRODUCT_MAP`）。

**9 分关注线**用于：对内体验 P1、产品「重点改善」、对外混算「9 分以下产品数」。对内体验统计 9 分以下产品时**排除小样本**（极低分除外）。

**88% 达标线**只用于投诉回访 10 分率。比较用 0–1 小数：`!smallSample && rate < 0.88` 为未达标。工单 `followUpSatisfaction` 另有一套同公式的月度 10 分率（`TEN_POINT_SATISFACTION_BASELINE=0.88`），服务工单侧分析，**不替代**用后即评 callback 渠道指标。

### 8.3 非 10 分与评分分布

- 非 10 分：`score < 10`（与 `!== 10` 在整数分下等价；分布前对得分 `.round()` 再入 1–10 档）。
- 分布表产品：月报得分表中「均分不是 10 **或** 存在非 10 分」的产品。

### 8.4 客户原话与正负

统一过滤，供负面纳入、原话登记、报告证据共用。

**取数：**

| 渠道 | 文本 |
| --- | --- |
| 评分类 / 选项类 | 反馈原因列表，缺省回退 `commentText` |
| 短信 | 整体补充评价 |
| 投诉回访 | 电话回访意见 |
| — | **不用**不满原因字段冒充原话 |

**无效文本：** `无`、`无/不涉及`、`/`、`业务使用完毕`、`其他`、`nan`、纯数字、纯字母。

通过过滤后：与固定原因清单**全文相同**（不含「其他」）→ **反馈选项**；否则 → **客户原话**。

正负先对齐 10 分满意 / 非 10 分，**10 分自由文本再跑语义**（复用工单情绪分析：轻度不满 / 不满 / 强烈不满视为负）：

| 极性 | 规则 |
| --- | --- |
| 负反馈 | 反馈选项；或有效自由文本且得分不是 10（无分也按负）；或有效自由文本得分为 10 但语义为负 |
| 正反馈 | 有效自由文本、同一条记录得分为 10，且语义不是负 |

均分、10 分率、产品状态仍按得分计算，不因原话改判而改分。问题条优先挂负向原话（没有再挂最多 2 个反馈选项）；同产品正反馈只收语义仍为正向的 10 分原话。本月判断各摘最多 3 条正/负原话。

### 8.5 固定原因清单

控制台（18，含其他）：功能有缺失；任务操作流程不够简单快捷；缺乏操作指引；不满足业务部署要求；内容/帮助说明不易懂；稳定性不足故障频发；页面打开慢；界面布局不合理；帮助文档说明不清晰；服务不好用/操作过于复杂；找不到需要的产品/功能；存在网络安全问题或风险；自助解决支撑不足；内容/帮助说明不充分；产品价格没有优势；购买时参数/配置选择错误；服务故障频发/无法修复；其他。

投诉回访（6，含其他）：未解决；处理周期长；业务规则；产品质量；服务人员的业务能力；其他。

匹配：规范化后的语料 `includes(标签)`，一条可多标签。「其他」「业务使用完毕」「空白」不进原因柱状图。

### 8.6 客服部回访在分析里怎么用

不改变均分。按产品名，或客户名称/编码出现在回访 `userInfo` 中，挂到产品总览、需求、客户表（`visitEvidenceCount` / 回访结论）。需求与回访的弱关联：回访文本包含该需求标签。

### 8.7 月报 KPI 取值

| 内容 | 线上 | 月报 |
| --- | --- | --- |
| 用后即评评分 | 当前周期、已开分析的产品 | URL 月份对应的线上结果 |
| 云网均分 vs 公司 | 工作台分列展示 | 同月对外混算：`云网均分 − 公司均分`；无公司样本则「暂无公司均分对比」 |
| 云网均分环比 | — | 同口径上月云网均分：`本月 − 上月`；无上月样本则「暂无上月对比」 |
| 客服部回访 | 导入数据月份跟随当前范围 | 与报告月相同 |
| 产品目录 | 当前生效目录 | 复用线上目录 |
| 问题变化 | 当前月 vs 之前最近有数据月 | 截止报告月，禁止未来月 |
| 举措 | 当前产品范围 | 本月提出、本月关闭及效果验证 |

## 9. 计算链路与落盘

```text
filterRecordsForScope(period, post_use_rating)
  → scopePostUseRatingRecords(analysisPostUseRating)
  → postUseRecordsToScoredRows（去掉选项类，要求有分）
```
