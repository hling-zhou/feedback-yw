# Feedback Insights 用户使用手册

面向产品、运营与分析人员：从反馈数据到 **周期结论** 与 **行动建议**，并在需要时下钻到单条工单。

---

## 系统能做什么

| 你要的结果 | 系统提供 |
|------------|----------|
| **看清本期重点** | 按洞察周期汇总多来源反馈，给出摘要、分维度解读与图表 |
| **支撑产品讨论** | 归纳 **行动建议**（优先级、范围、依据工单），供规划参考 |
| **追根因、核样本** | 从结论或图表点进单条反馈，查看/修正标签与人审意见 |
| **持续更新数据** | 导入新批次、修正打标后刷新洞察，结论随数据更新 |
| **对外汇报** | 导出 PDF 报告或分析结果 |

数据来源包括：投诉工单、咨询工单、用后即评等（工作台按来源分 Tab）。

---

## 怎么用

### 日常阅读（查看者即可）

1. 登录后进入 **洞察工作台**（默认首页）。
2. 用顶部 **洞察周期** 选择要看的月份/季度/年。
3. 若页面提示快照过期或暂无内容，点击 **「生成 / 刷新洞察」**（需编辑者操作，或请同事刷新）。
4. 在 **综合概述** 阅读：
   - **周期洞察概览** → 摘要与分维度洞察  
   - **行动建议** → 详细意见与依据工单（可点工单号看原文）
5. 需要看某一类反馈时，切换到 **投诉工单 / 咨询工单 / 用后即评** 等 Tab；需要更细维度时，点 **洞察分析**（问题类型、旅程、情绪、高频词等）。
6. 汇报时用 **导出 PDF**。

### 导入新数据（编辑者 / 管理员）

1. **数据导入** → 选来源与 **数据月份** → 上传 Excel/CSV → 映射列 → 确认导入。
2. 导入完成后到 **洞察工作台** 选对应周期，点击 **「生成 / 刷新洞察」**（导入流程有时会自动生成，以页面提示为准）。
3. 在 **反馈库** 核对条数是否合理。

> **洞察周期** = 分析用的时间窗口；**数据月份** = 导入时标注的反馈所属月份。两者需对应，否则该周期可能无数据。

### 修正打标、提升结论质量（编辑者 / 管理员）

仅在标签不准、旅程大量「未识别」、或需补充人审意见时使用：

1. **反馈库** 筛选 → 打开工单详情 → 改 **情绪 / 请求场景 / 问题类型 / 用户旅程**，或填写 **根因、解决方案、优化举措** → 保存。
2. 批量问题时用 **批量重新打标**；若已配置 LLM 但部分工单未增强，反馈库顶部会显示紧凑提示条，可直接点 **补打**（客户请求/痛点/优化建议）或 **补打旅程**（无需再选范围，按对应 scope 直接启动）；也可用筛选 **待 LLM（请求/痛点/优化）** / **待旅程 LLM** 后通过工具栏批量重打。改完回到工作台 **「生成 / 刷新洞察」**。
3. 若是 **标签体系** 本身不全：到 **分析维度** 维护产品、旅程、问题类型等 → **发布** → 再重新打标并刷新洞察。
4. 需 **万投比** 时，在 **设置** 维护各产品 **月订单数**。

### 首次启用（管理员 / 配置负责人）

按顺序做一次即可：分析维度维护产品与旅程 → 发布配置 → 设置洞察周期与打标策略（可选）→ 导入首月数据 → 生成洞察 → 在 **用户管理** 创建同事账号。

---

## 必记一点

**导入、改标签、批量重新打标之后，结论不会自动立刻变**——需在工作台点击 **「生成 / 刷新洞察」**，图表与行动建议才会与最新数据一致。切换周期后若出现黄色过期提示，同样需刷新。

多人共用同一地址时，页面约数秒同步；若与同事看到的不一致，确认访问的是同一服务器，并等待对方刷新完成。

---

## 遇到这些情况

| 情况 | 怎么做 |
|------|--------|
| 工作台空 / 「请先生成洞察快照」 | 确认该周期已导入数据 → **生成 / 刷新洞察** |
| 行动建议很少或没有 | 该周期样本偏少；补充导入或换更大周期 |
| 万投比为「—」 | **设置** 补该产品当月订单数 |
| 旅程大量未识别 | **分析维度** 查旅程配置 → 发布 → 反馈库重新打标 → 刷新洞察 |

账号与登录问题联系团队管理员。
