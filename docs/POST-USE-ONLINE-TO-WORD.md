# 用后即评线上看板与 Word 月报关系

## 定位

- 线上看板是权威分析层：支持任意时间范围的系统性、综合性分析与证据下钻。
- 当前 Word 报告仅提供月度发布视图：不维护另一套指标或洞察规则，只把所选月份的线上结果按固定章节组织、排版和导出。年度报告属于后续规划，当前不提供入口或生成逻辑。
- Word 只能在选择单月时生成，报告月份等于当前选择月份。

线上综合分析采用固定叙事顺序：范围与可信度、综合结论、体验现状、趋势变化、原因与用户需求、客户与证据、行动、效果验证、分析附录。章节不使用编号，避免编号干扰连续阅读。投诉回访满意度属于体验现状指标，客服部回访属于跨章节补充证据，均不建立独立一级模块。

## 数据范围

| 内容 | 线上范围 | Word 取值 |
| --- | --- | --- |
| 用后即评评分 | 当前时间范围内、已开启用后即评分析的产品 | 所选报告月的线上结果 |
| 客服部回访 | 按导入时选择的数据月份跟随当前范围，作为产品、需求、客户和举措的补充证据 | 与报告月份相同，不再自动前移一个月 |
| 产品目录 | 当前生效的产品与规格配置 | 复用线上目录版本 |
| 问题变化 | 当前月与其之前最近一个有数据月份 | 截止报告月计算，禁止引用未来月份 |
| 举措 | 当前产品范围内的举措 | 本月提出、本月关闭及效果验证 |

历史客服部回访记录若没有 `importMonth`，兼容使用 `visitMonth` 作为数据月份；重新导入后将显式保存 `importMonth`。

## Word 固定章节

1. 当月概述：产品数、样本量、均分、低分比例、投诉回访满意度、数据质量和规则版本。
2. 线上综合分析：产品体验状态、评价触发场景×用户旅程、用户需求改善优先级、高频低分客户、问题变化。
3. 客服部回访：Word 保留月度发布所需的回访明细；线上看板不设独立回访模块，回访内容融入产品、需求、客户与举措分析。
4. 原因证据：选项类与非10分原因聚合。
5. 举措与效果验证：洞察主题、举措、证据数、推进/恢复状态，以及已完成但未恢复项。

## 单一计算链路

`当前时间范围 → 产品范围过滤 → 质量快照 → 线上洞察包 → 月报模型 → 页面预览 / Word`

页面预览和 Word 使用同一个月报模型；新增报告字段时必须先进入线上洞察包或月报模型，禁止在 Word 生成器内另写统计规则。
