## 2. 已知坑与先例（结构约定）

### 2.1 状态与生命周期类（详见防缺陷触发规则 §1/§2）

- 归档（jira_items）与勾选（decisions）双存储独立——**完结动作必须联动清理决策态**（archiveMany/upsertMany/delete/deleteMany 全入口），存量矛盾对一次性回填清理；禁止用呈现层"已纳入优先显示"压矛盾（第 N 个消费方必然漏出）。
- 联动/兜底路径的 catch **必须外显 linkageError** 并写审计——只 log warn 时故障穿上成功外衣（"成功但计数 0"无法区分"没有匹配"与"联动坏了"，11-10 定位绕三轮）。
- UPDATE 不存在的行 changes=0 **静默无效**——修复脚本类 INSERT OR REPLACE + changes=0 中止（11-10 一天三次静默失败家族）。
- 旧格式无月份 dispatch 标记（`q:客户:产品`）在 itemKeySubsetMatches 兼容分支会**跨月串扰**——存量兜底分支仍在代码里，处理存量数据时注意。

### 2.2 UI 结构类（详见页面UI规范.md）

- 外壳统一 padding（px-3→sm:px-4→lg:px-5），页面外层 space-y-4 禁自包 p-6；page-card 体系 + 14px 卡片标题；禁 antd Card / Title level={5} 当页面卡片标题（弹窗标题豁免）；新建组件先抄先例；存量随改随清。
- 卡片内 Table 表头吸顶 = stickyOffset 测量传递机制（FeedbackTable/CustomerVisitTable 同款），新视图照抄。
- 列表页 antd Table scroll.x 模式下，**列宽拖拽必须走 columns.width 重渲**（rAF 节流 setState），直接写 th.style.width 不生效（11-11 antd 机制坑）；fixed 列/操作列/无 width 弹性列不参与拖拽。

### 2.3 服务端/数据类

- **服务端进程内产品目录缓存易陈旧**：新消费方读 getCatalogProducts() 前必须 loadManagedProductCatalog 刷新（先例 refreshProductCatalogForReminder，已扩 MCP/patrol 线；守卫 catalogCacheCoverageGuard）。
- **路由内动态 import 按顶层导出解构对象内部方法 = undefined**：方法挂在 repository 对象内部时，`const { method } = await import(...)` 静默 undefined → 调用抛错被 catch 吞成"成功但 0"（11-10）。差分定位法：独立调用成功 vs 路由内失败 → 打印 import 解构结果。
- **payload LIKE '"importMonth":"x"' 预过滤依赖 JSON.stringify 键序**，脆弱——改全表扫描 + 内存匹配（deleteByIdentity 先例）。
- 路由级测试绕过 requireAdmin：onRequest 注入 `request.user = { role: 'admin' }`；测试文件先设 `AUTH_DATABASE_PATH` 再动态 import。
- 数据库加列走"加列不改列"（先例 migrateMailGroupCcColumn 挂 initBusinessSchema，pragma 检查幂等）——旧数据天然兼容、读侧零包袱。
- whats-new：prebuild 生成，范围 scripts/whats-new.since..HEAD 勿前移；维护类提交一律 `Changelog: skip`。

### 2.4 LLM/解析类

- LLM 分阶段串行：sharedDimensions(8) → ticketLlm(4) → 维度重打标 → journey(8) → 主题情绪（本地）；中间结果仅 ticketLlm 阶段流式写盘。
- 流式写盘：规则重打标每 4 条、ticketLlm 每 4 条；取消 = META_KEY 协作式；任务结束自动释放锁。
- curated taxonomy 与 sharedTagDefs 是**两套独立词表无同步机制**——补词要两边都补（11-10 对照修复教训）。

## 4. 设计级变更流程（拍板前必读）

改键粒度 / 存储结构 / 口径这类设计级问题 = **变更管理**，不按普通 bug 修：

1. **隐含业务假设写成一句话请业务方确认**（"处理一次是永久处理，还是按月独立？"）——假设没确认不算设计完成。
2. 全消费方清单 → 逐个验证 → 迁移方案 → 真实链路验证。
3. 排查现象先分层归因：dump 实际数据形态再定方案——"设计本来如此" vs "实现没生效"是两个完全不同的修复面，修错方向白走一轮迁移。
