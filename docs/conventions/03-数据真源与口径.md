## 2. product / productName 双字段口径（11-07 拍板）

| 字段 | 语义 | 空值情况 |
|---|---|---|
| `product` | 解析产物，**展示名真源** | 投诉/咨询零空值 |
| `productName` | 用后即评导入原始列 | 可能规格粒度；投诉/咨询恒空 |

- **读记录产品名一律 `record.product || record.productName`**——新消费方照抄此双读模式，禁止单读一边。先例：`server/observationRepository.js:104`、`server/generalizationRepository.js:118`、`server/reminderRuleEngine.js`。
- 归组解析走 `resolveActionItemProductDisplayName` + `buildProductNameByKeyMap`。
- **禁止擅自统一/重命名这两个字段**：属数据模型级变更，已记入 05 文档待拍板清单，短期双读+守卫兜底。
- **读记录字段报"数据缺失"→ 必先 dump 真实 payload 字段形态再归因**——"缺失"常实为"读错字段"（11-07 先例：提醒邮件英文 key，根因是消费方读错字段名，数据一直有值）。

## 3. 打标闸门与请求节点解析

- 打标闸门三级：**L0（CR 质量 + 意图置信度）→ L1（scene×type 一致）→ L2（journey 有效+方向）**，失败落 manual_review。
- **请求节点解析唯一入口 = `src/lib/ticketAnalysis/pathSegments.js` 的 `parseRequestNodeSegments()`**——不要另写解析。
- 分类判据以「处理意见」实际问题+处理结果为真源（口径 = `split('处理意见：')[-1]`）；请求节点无区分力；决策树未命中时 LLM 语义匹配（strictLabels 只选不造）。
- 旅程打分器：报「不通」且胜出节点是同 L1 质量节点 → `correctQualityWinnerToConnectivity` 改判；corpus 小写，方向正则加 /i（11-10 curated 修复教训：引擎 seedMatchers 区分大小写且语料不 toLowerCase →「PING 不通」永远匹配不上小写 ping）。
- 用后即评旅程补全：`classifyPostUseJourney` 四分类 auto / llm_unknown / legacy / none；llm 已判未识别默认不计数不重试；旅程门闸 manual_override 判据 = manualTagFields 含 journey。

## 4. LLM 解析层契约（11-06 沉淀）

- `parseLlmMessageContent` / `parseLlmResponseBody` **原样保留 `{results:[...]}` 批容器**。
- 动 `pickAssistantPayload` / `collectBalancedJsonSlices` 必跑 `src/lib/llmClient.test.js` 契约守卫。
- 消费方场景不同（assistant 单对象 vs 打标批容器）→ 形态判定显式分支，不得一个启发式通吃（82742ef 教训：一个"取最后完整对象"启发式剥掉批容器，6+ 消费方批量答案丢失 28 天）。
- **journeySource 如实标注**：模型真实判断标 `'llm'`；答案未送达回退本地重匹配的，标 `'rule'`（来源标注失真 = 下游口径全歪，详见防缺陷触发规则 §7）。

## 5. 服务端产品目录缓存（易陈旧共享态，10-25 根因）

服务端进程内产品目录缓存会陈旧。**任何新消费方读 `getCatalogProducts()` 前，必须先 `loadManagedProductCatalog` 刷新**：

- 先例：`refreshProductCatalogForReminder`（reminders，88cdb39），已扩至 MCP 与 patrol 线（patrolCompress / patrolDiagnose 取 catalog 前都加了刷新）。
- 守卫：`catalogCacheCoverageGuard`（reminders/MCP/patrol 三线覆盖）。

## 7. 列表投影与脱敏

- 列表接口 `fields=list` 裁掉 rawText/handlingText 等大字段；前端搜索对工单加 sourceColumns 回退。

## 9. 身份键与覆盖语义（11-10 拍板）

- 省代表回访**身份键 = 同月 + 同产品 + 同客户**（stableVisitRecordId）；导入同身份覆盖旧条、人工域保护（manualEditedFields 域级标记：internalEvaluation/assigneeName/remark）。
- **身份判定必须按三元组，不能按 id 形态**（11-10 幂等缺陷先例：老记录字符串 id 与预导入哈希 id 同身份不同 id → 重复）。
- 导入覆盖语义 = "导入值优先但人工已填不冲掉"；重复导入同条且内部评估列为空，会把已评估抹回待评估——"导入 = 最新事实覆盖"的既有语义，如实呈现。
- dispatch 已纳入标记 / decisions 勾选与回访记录、jira 条目的**删除/完结联动**见防缺陷触发规则 §1（linkageError 外显要求见 §2）。
