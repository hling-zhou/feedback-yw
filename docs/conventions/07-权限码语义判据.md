# 07 · 权限码语义判据

> 出处：2026-11-20 复盘（「产品侧处理反馈」误用 manageTags 门控，partial_editor/viewer 13 天看不到反馈表单）。
> 真因：动作客体是**业务记录**却套了**配置资产**的权限码——选码靠直觉、无判据层拦截。
> 守卫：`src/lib/gateConsistencyGuard.test.js`（同构权限一致性守卫，登记表驱动）。
> 适用：写任何 `can(code)` / `requirePermission(code)` / `assertWritePermission(...)` 之前——先查本文判据，再选码。

## 核心分界（一句话）

**动作的客体是「一次性业务记录」还是「长期配置资产」？**

- 记录 → `editRecord` 系（改的是某条数据本身，影响仅此一条）；
- 配置 → `manageTags` 系（改的是规则/体系，影响后续全量行为）。

用**管理权限码门控消费动作** = 把业务干将挡在门外（先例：partial_editor 填处理反馈被 403 13 天）。

## 同构动作判据（第二把尺）

同一业务动作（复用同组件/同语义）出现在多模块时，**门控码必须一致**：

- 先例：`EstablishedActionFields`（确立举措）三宿主——反馈库抽屉/巡检失败组抽屉/待办抽屉，全 `editRecord`；
- 反例（已修复）：巡检失败组抽屉填处理反馈用 `manageTags`，同库同构的反馈库抽屉用 `editRecord`——判定漂移，用户侧表现为「有的账号看不到」。

**选码三步**：① 查判据表定客体（记录 vs 配置）；② grep 同组件/同语义动作的其他宿主，核对既有门控码；③ 新宿主接入共享组件时，登记进守卫的 `SHARED_COMPONENT_HOSTS` 表（漏登记被「未登记宿主兜底」用例拦红）。

## 写路由权限码断言（登记表）

| 路由 | 权限码 | 依据 |
|---|---|---|
| PATCH `/api/patrol/failures/groups/:id`（处理闭环） | editRecord | 11-20 拍板；客体 = 失败组的处理反馈记录 |

新增「处理反馈类」写路由时在此登记一行，守卫的 `ROUTE_GATES` 同步。

## 矩阵外硬编码 admin 检查（requireAdmin）

投诉原因审查 / 提醒邮件预览发送 / 行动建议删除 / 巡检手动处理触发 / 需求工单进度手动刷新 / 用量统计 / 全库导入备份 / 批量重打 period_all scope / 用后即评建议回访清单（admin+editor）。新增 requireAdmin 调用时同步更新权限文档（docs/ 下角色权限清单类）。

## 维护

- 新增权限码入 `ROLE_PERMISSIONS` 时：本文判据表**必须同时落一行**（无判据即被 review 拦）；
- 新增共享业务组件（多宿主复用形态）：登记进守卫 `SHARED_COMPONENT_HOSTS`；
- 本文档判据与守卫登记表不一致时，以**用户最新拍板**为准并双处同步。
