## 1. 如何使用

| 字段 | 含义 |
|------|------|
| **ID** | 唯一任务编号（G = generalization），PR/日志引用 |
| **估时** | 单人日（d），含自测 |
| **依赖** | 必须先完成的任务 ID |
| **涉及文件** | 主要改动点，非穷尽 |
| **验收** | 完成判定标准（与设计 §8 一致） |

**建议迭代**：G0 → G1 → G2 → G3；G0 与 G1 可部分并行（G1-1/G1-2 依赖 G0-6 client，G1-3 起可与 G0-5 并行）。G4 为 P2 可选项。

**✅ 设计文档同步说明（00:13 已消除矛盾）**：设计 §8.1 G0-7 已改为"不注册新 enrichRunner mode，由 observationScanRunner 尾部调用"——与 §4.2 及本清单口径一致。两份文档当前无冲突；执行口径以本节为准：不注册新 mode；G-pass/M-pass 逻辑放 `server/generalizationScanRunner.js` 导出的执行函数，由 `observationScanRunner.runObservationMatch` 尾部调用（同一后台任务、同一 lock、同一 LLM transport）；手动补跑 `POST /api/generalization/scan` 内部启动 mode=observation_match 任务并带 `generalizationOnly: true` 参数（跳过留观段只跑举一反三段）。
