# 行动建议 · 分类过程与规则（落地版）

> 版本：v1.0 ｜ 日期：2026-09-08
> 适用范围：洞察工作台「行动建议」模块 · 云专线 / 弹性公网IP / 虚拟私有云 / 弹性负载均衡
> 数据源：`data/反馈库7月–8月.xlsx`（投诉/咨询工单，按月分 sheet）
> 实现：`scripts/validate-action-recs.cjs`
> 前置阅读：`docs/二次验证-分类思路与四产品结果.md`（本规则的验证依据与已知缺陷）

## 一、这套规则要解决什么

把一个月内几千条工单，收敛成**几件值得下个月动手的事**。不是做一张分类统计表——分类只是手段，**"该做什么"才是目的**。

因此本规则有两条硬红线：

1. **不追求零未归类**。硬把每单塞进某个类，只会制造虚假的完整性。未归类率 <5% 即可，剩余如实披露。
2. **不追求全自动化**。机器负责收敛到"值得看"的量级，人负责最后一道判断。规则的设计目标是**减少人工量，不是消灭人工**。

## 二、分类原则（4 条，改分类法时不得违反）

### 原则 1：按「问题原因」聚类，不按「客户动作/表面主题」

- ❌ 错误：按"客户做了什么"建家族（创建申购 / 退订释放 / 绑定解绑 / 到期冻结）
- ✅ 正确：按"为什么出问题"建家族（容量与资源不足 / 配额有效期与回收 / 审批流程不透明）

> 反例教训：EIP 曾按动作建家族，导致「配额不足」与「带宽扩容被卡」两个家族各有一个"资源不足"子议题——同一根因被劈成两处，两边都显得量小，反而不显眼。

### 原则 2：原因优先，痛点兜底

每条工单按此优先级取分类依据：

```
问题原因（人工复核/自动生成的根因）  ──命中──▶ 用它
        │ 未命中 或 是样板句
        ▼
需求痛点（分析层摘要）                ──命中──▶ 用它，并标记"痛点兜底"
        │ 未命中
        ▼
      未归类（如实计入未归类率）
```

**为什么必须兜底**：实测 EIP 有 **59.6%** 工单的 `问题原因` 是样板句"工单未定位到具体问题原因"（无根因）。不兜底，未归类率会飙到 60%。

**兜底的代价要认**：痛点命中的标签来自分析层摘要，精度低于原因命中。抽样核查中**误归几乎全部发生在痛点命中组**。故痛点兜底命中的家族，对外发布时应标注"根因待人工确认"。

### 原则 3：横切项不并列为缺陷家族

"文档/自助能力缺口""缺乏自助诊断工具"这类**非产品缺陷**的咨询，单独标记 `crossCut: true`，移出 5 层信号、单列披露，**不与缺陷原因家族并列**，避免把"用户不懂"当成要优化产品的根因。

### 原则 4：未定位不伪装

`问题原因` 为样板句、且痛点也命中不了具体子议题的工单，路由到独立桶 **`未定位·无根因模板`**：不计入"其他/通用"规模、不参与子议题挖掘、不进入 5 层信号，仅在附录透明披露。

> 教训：不剔除样板行，会把模板噪声当主题，并让"其他/通用"占比虚高（EIP 曾虚高到 19.4%，剔除后降至 3.7%）。

## 三、分类流程（7 步，每月复跑）

```
① 数据接入
   xlsx 四 sheet（投诉/咨询 × 上/本月）→ 合并，保留 _sheet 与 _src（投诉/咨询）
   月份从 _sheet 解析（如"咨询2026年8月"）；注意 受理内容 字段无日期
   ⚠ 每次换数据源先做保真核对：行数 + 工单号一一对应 + 关键字段抽样比对

② 取分类依据
   问题原因 / 需求痛点（按原则 2 的优先级）

③ 家族匹配（L1）
   按 TAX 中家族顺序 first-match-wins，命中即停
   ⚠ 家族顺序影响结果——见 §六 缺陷 B

④ 子议题匹配（L2）
   在命中家族内，按子议题顺序 first-match-wins
   未命中子议题 → 按原则 4 分流：样板根因 → 未定位桶；否则 → 其他/通用桶

⑤ 其他/通用 自动细分（autoSplit）
   对偏大的"其他/通用"桶自动挖 L2，产出 docs/L2自动细分-提案.md
   人工确认后把 {key,name,re} 加进 TAX → 转常驻正则

⑥ 5 层信号分层
   用相对化阈值把子议题分入：长期结构性 / 本月异动 / 小而锐·高害 / 常规迭代池 / 平稳长尾

⑦ 生成与复核
   输出人读备忘录 + 模块视图；按 §七 复核清单过一遍再发布
```

复跑命令：

```bash
node scripts/validate-action-recs.cjs              # 常规复跑
AUDIT_SAMPLE=1 node scripts/validate-action-recs.cjs  # 附带分类审计抽样
EXPORT_JSON=1 node scripts/validate-action-recs.cjs   # 导出家族计数（供横向对照）
node scripts/export-cause-crossprod.cjs               # 生成跨产品横向对照表
CAUSE_FIRST=0 node scripts/validate-action-recs.cjs   # 回退旧分类法对照
```

## 四、因地制宜：四产品各自一套 TAX，不共用

**为什么不能一套正则套四产品**：四产品业务形态不同（公网 IP 配额、专线物理链路、VPC 网络配置、LB 转发），共用的结果就是每边都分不准。

| 产品 | 体量 T | 投诉基线 B | 家族数 | 未归类率 | 设计要点 |
|---|---|---|---|---|---|
| 弹性公网IP | 2393 | 5.6% | 16 | 1.4% | 体量最大、家族最细。配额类拆成 3 个独立家族（容量/有效期/审批） |
| 云专线 | 113 | 26.5% | 7 | 0.0% | 物理链路 + 订购变更流程主导，家族从简防过拟合 |
| 虚拟私有云 | 122 | 40.2% | 9 | 4.1% | 安全组/内网连通为大宗；本轮已把"计费与概念误解"降级为横切项 |
| 弹性负载均衡 | 75 | 22.7% | 9 | 1.3% | 体量最小，家族数已接近上限，再细即过拟合 |

**家族数与体量的经验关系**：

- T ≥ 1000 → 可支撑 12~16 个家族
- 100 ≤ T < 300 → 6~10 个家族，单家族 <5 单的考虑合并
- T < 100 → 家族数 ≤ 10，且任何家族 <3 单时不出卡片（进长尾）

### 阈值必须按产品相对化（禁止全局阈值）

四产品体量差 32×、投诉基线差 7×，用全局阈值必然误判。

| 阈值 | 公式 | EIP | 云专线 | VPC | ELB |
|---|---|---|---|---|---|
| H 高害（小而锐门槛） | `min(100%, max(17%, 1.5×B))` | 17% | 40% | 60% | 34% |
| S 结构性 | `max(10, round(0.10×T))` | 239 | 11 | 12 | 10 |
| L 长尾 | `max(3, min(10, round(0.01×T)))` | 10 | 3 | 3 | 3 |
| Δ 异动绝对量 | `clamp(round(0.05×T), 3, 12)` | 12 | 6 | 6 | 4 |

三条护栏（缺一不可）：

1. **小而锐最小样本 `n ≥ 3`**：否则 1~2 单 100% 投诉会被夸大成"小而锐"。不足则归长尾并打"⚠高害信号·需确认"。
2. **异动双判据**：`|环比%| ≥ 50%` **且** `|Δ绝对| ≥ Δ`。只看环比，1→3 单会误报 +200%。
3. **H 用 `max(17%, 1.5×B)` 而非 `min(100%, 3×B)`**：后者在 VPC（B=40%）会封顶 100%，只剩全投诉项才触发，漏报中等高害。

## 五、可持续：换月份、换产品不用重写

| 机制 | 作用 | 实现位置 |
|---|---|---|
| **自动 L2 细分** | "其他/通用"大桶自动挖子议题，无需手写正则 | `autoSplit()` |
| **样板根因剔除** | 模板句不计入挖掘、不进 5 层，防噪声当主题 | `isBoilerplateReason()` |
| **阈值相对化** | 换产品/换月份自动重算 S/L/Δ/H | `thresholds(T, B)` |
| **人工确认提升** | 自动细分提案经人工确认后加进 TAX，转常驻正则 | `docs/L2自动细分-提案.md` |
| **回退开关** | `CAUSE_FIRST=0` 一键回退旧分类法对照 | 主循环 |
| **分类审计抽样** | `AUDIT_SAMPLE=1` 输出每条工单命中明细，供复核 | 主循环守卫块 |

### 自动 L2 细分的四步与三个坑

**四步**：去样板 → 选组（有效词中出现行数最多）→ 定名（整组共有、且桶内其余行都没有的最长公共子串）→ 护栏（组内集中度 ≥50%，最多 4 组）。剩余如实留在"其他/通用"，**绝不硬拆**。

**三个反直觉的坑**（都已处理，改代码时勿回退）：

1. **不去样板会把模板噪声当主题**——必须先切掉产品内出现率 ≥20% 的模板句。
2. **截断碎片 df 反而最高**——噪声词整词被否后，其半截形式（`"线连"` ∈ `"专线连通"`）出现行数反而最高。**必须在选组环节就挡掉**，否则选出来的永远是最没意义的碎片（早期版本产出过"单未定/客户对/仅支"）。
3. **样板根因会虚高集中度判断**——模板行同时出现在"已分类行"里，会让 autoSplit 误判"与现有子议题同质"。必须先剔除再算集中度。

## 六、缺陷的技术解法（已落地，不依赖人工复核）

> 背景：2026-09-08 二次验证发现三类系统性缺陷（泛词误吸 / 顺序依赖 / 痛点放大）。
> 解法：**把「正则 first-match」升级为「区分度加权 best-match」**，全部机制化、可自进化。

### 引擎总览

| 缺陷 | 技术机制 | 实现 |
|---|---|---|
| **A 泛词误吸** | **区分度加权**：词权重 = IDF × 专属性 × 泛词惩罚。被多家族当作种子的词自动降权（spread≥3 罚 0.3、≥2 罚 0.6） | `learnWordWeights()` |
| **B 顺序依赖** | **best-match 取代 first-match**：所有家族打分取最优，家族顺序不再影响结果 | `scoreFamilies()` |
| **C 痛点放大** | **字段权重**（原因 ×1.0 / 痛点 ×0.6）+ **缺失/否定子句加权 ×1.5**——"缺乏…指引"是问题陈述，"导致…影响业务"是后果噪声 | `FIELD_W` / `NEG_CUE` / `scoreText()` |
| **质量自证** | **置信度门控** `conf=(top1−top2)/top1` + **证据门控**（纯痛点 ∧ 仅命中 1 词 ∧ 分数处最低 20% → 自动隔离） | `classifyScored()` |

### 自举学习（自进化 / 自适应的核心）

权重**每期从当期语料自动重算**，换产品、换月份、换工单形态都无需改代码：

1. **第 1 遍**——识别"独占样本"（只命中单一家族种子词的工单）。泛词会命中多个家族 → **不进独占样本** → 权重统计天然不被污染。
2. **第 2 遍**——统计每个词的 `dfAll`（全语料出现率）与本族/他族分布 → 算 `IDF × 专属性 × 泛词惩罚`。
3. **自适应阈值**——置信度阈值取当期 conf 分布的 15 分位（clamp 0.08~0.30）；弱证据阈值取分数分布 P20。**均不硬编码**。

### 实测效果（2026-09-08）

| 产品 | 旧未归类 | 新未归类 | 待确认（自动隔离，不进 5 层） |
|---|---|---|---|
| 弹性公网IP | 1.4% | **1.5%** | 8.9% |
| 云专线 | 0.0% | **0.0%** | 12.4% |
| 虚拟私有云 | 4.1% | **2.5%** | 12.3% |
| 弹性负载均衡 | 1.3% | **1.3%** | 10.7% |

覆盖率不退化（VPC 反而 4.1% → 2.5%）。原误归案例复核（`CHECK_ID=工单号`）：

| 案例 | 原归属 | 新归属 | 结果 |
|---|---|---|---|
| "流程中断"（配额申请因账号错误） | 网络故障 ❌ | 容量与资源不足 | ✅ 已修 |
| "轻载IP产品介绍与购买指引" | 拥塞/轻载通道 ❌ | 网络链路质量 | ⚠️ 未修（`hitN=1`） |
| "配额提升审批依据不充分" | 容量与资源不足 ❌ | 容量与资源不足 | ⚠️ 未修 |
| "专线带宽未生效" | 网络链路与中断 ❌ | 开通订购与变更流程 | ⚠️ 未修 |
| "子网删除入口不明确" | IPv6/双栈子网 ❌ | 子网路由与双栈 | ⚠️ 未修 |

### ⚠️ 残余局限（诚实披露，不要假装已解决）

**词义消歧是本质难题，纯词权重解决不了。** 剩余案例的共性是 `hitN=1`（仅 1 个词命中）——
"子网删除" vs "子网IPv6"、"轻载IP产品" vs "轻载通道"、"带宽未生效" vs "带宽变更"，
需要**搭配/句法级**理解（哪个是动作、哪个是修饰对象），不是单词权重能区分的。

系统的应对是**自动识别并隔离**（证据门控：纯痛点 ∧ `hitN<2` ∧ 分数 P20 以下 → 待确认桶，不进 5 层信号），
而非硬归类。这才是"不依赖人工复核"的真正含义——**系统自己知道什么不确定**。

若要进一步消除（技术手段、非人工）：
- 对证据单薄工单引入 **LLM 语义判断**（只处理 `hitN<2` 的少数单，成本低）
- 引入 **n-gram 搭配特征**，把"子网删除""带宽未生效"作为整体短语学习

### 实现踩坑记录（改代码时勿回退）

1. **提取种子词绝不能跳过含正则元字符的模式**（如 `无法满足.*需求`）——跳过会丢匹配能力，实测 VPC 未归类率 4.1%→8.2%。
2. **不要用绝对分数阈值判未归类**（权重量纲随产品/月份变化）——应判"完全未命中"，否则覆盖率无谓退化。
3. **子议题扁平打分不可取**——子议题正则覆盖不全（家族正则才含全部词），实测待确认率飙到 14.7% 且已修案例退化。
4. **证据强度不要乘进 conf**——会误伤大量正常单（待确认率 28%），应作**独立门控**。
5. **置信度阈值上限不要设 0.5**——conf≥0.30 已表示 top2 ≤ 0.7×top1，再高会把大量正常单误隔离。

## 七、发布前自动门禁（脚本自动执行，非人工核对）

> §六 保证**分类质量**，本门禁保证**这一期能不能发**。
> **全部由脚本自动判定**——跑完即出 PASS/FAIL，无需人工逐项核对。

每次 `node scripts/validate-action-recs.cjs` 自动输出门禁结果（`PREFLIGHT=0` 关闭）：

| 检查项 | 判据 | 不通过的含义 |
|---|---|---|
| 数据保真·行数 | 原始 xlsx 行数 == 分析行数 | 中间产物与源不一致，结果不可信 |
| 数据保真·工单号 | 双向独有数均为 0 | 有工单丢失或多出 |
| 数据保真·字段 | 9 个关键字段抽样 0 不一致 | 字段被污染或丢失 |
| 未归类率（每产品） | < 5% | 出现了未覆盖的大项 |
| 待确认率（每产品） | < 20% | 分类法退化或数据质量恶化 |
| 小而锐样本（每产品） | 所有小而锐项 n ≥ 3 | 1~2 单 100% 投诉被夸大成小而锐 |
| 横切项单列（每产品） | 无 `crossCut` 项混入 5 层 | 非缺陷项混进了缺陷信号 |
| 出处标注（每产品） | 报告含〔痛点摘要〕/〔复核根因〕 | 疑似裸引分析层字段冒充客户原话 |

**接 CI 阻断**：`GATE_STRICT=1` 时任一 FAIL 以**退出码 2** 结束，可直接阻断发布流水线。

**阈值可覆盖**（因地制宜）：`GATE_MAX_UNCLASSIFIED`（默认 5）、`GATE_MAX_PENDING`（默认 20）。

```bash
# 常规：跑完自动出门禁（当前实测 PASS 23 / WARN 0 / FAIL 0）
node scripts/validate-action-recs.cjs

# CI 严格模式：任一 FAIL 即 exit 2
GATE_STRICT=1 node scripts/validate-action-recs.cjs

# 个别工单抽验（可选，非必须）
CHECK_ID=工单号 node scripts/validate-action-recs.cjs
```

> **门禁本身也需自测**：用 `GATE_MAX_PENDING=5 GATE_STRICT=1` 制造 FAIL，确认退出码为 2。
> 已验证：正向 exit 0 / 负向 exit 2 —— 证明门禁不是摆设。

## 八、字段出处纪律（红线，违反即返工）

报告中引述工单内容时，**必须按真实出处标注**：

| 字段 | 性质 | 用法 |
|---|---|---|
| `客户请求内容` / `受理内容` / `处理意见` | ✅ **真客户原声**（受理内容含客服记录） | 可作"真声"引用 |
| `需求痛点` | ⚠️ 痛点摘要（**分析层**，非逐字，含"增加操作成本"等判断，高度模板化） | 标〔痛点摘要〕，**不得当原话引** |
| `问题原因` | ⚠️ 人工复核/自动生成的**根因**字段（分析层） | 标〔复核根因〕，**不得当原话引** |
| `产品技术优化` | ⚠️ LLM 自动建议素材 | **只能放附录当"收敛素材"，严禁直接当建议**（会退化成堆候选动作） |

> 教训：曾把 `需求痛点` + `问题原因` 内容标成"用户原话"，属硬伤；也曾出现 `痛点摘要` 槽位错取 `产品技术优化` 首句、与 `建议` 显示同一串文字的串台。现已在 `mkItem()` 中分离：真声=客户请求内容/受理内容/处理意见；〔痛点摘要〕=需求痛点；〔复核根因〕=问题原因；建议=〔待人工收敛〕占位。

## 九、待办与已知局限

1. **修高泛词正则**（缺陷 A）——改动小、收益最大，建议优先。
2. **调家族顺序 / 加负向排除**（缺陷 B）。
3. **云专线 / ELB 尚未真重派**：当前是"沿用旧宽正则 + 按原因重新命名"，家族边界经验证站得住，但**原因纯度不及 EIP**（EIP 是用 `问题原因` 短语实挖重派的）。后续可做同款实挖。
4. **仅 2 月数据**：异动只有 1 个环比点，Δ 阈值需 ≥3 月基线后复核。
5. **误归率为抽样粗估**（非严格随机抽样），建议后续每期做固定种子随机抽样，跟踪误归率趋势。
