# 用后即评月季报自动文字稿

## 目标与触发

打开月报或季报后，报告立即展示证据规则稿；具备记录编辑权限且服务端已配置大模型时，自动为本期所有有评分的产品生成文字稿。只生成没有当前证据指纹对应稿件的产品。普通查看者读取已有稿件，不触发生成或写入。

产品文字稿包含负反馈详情、建议举措、评分概览结论。评分、样本、问题次数、问题排除状态和优先级仍由规则计算；已保存的人工结论和举措优先。省代表回访“无问题”只排除同客户、同产品、同一具体问题；原始评分、样本和原话次数保留。

## 数据流

1. 报告页等待本期及对比期评分记录、溯源、回访、问题关联和已存文字稿加载完成，再构建各产品证据指纹。人工叙述、行动事项、溯源、问题关联或已存稿读取失败时，不以空数据代替证据启动 AI 生成。
2. 仅将指纹不匹配或没有已存稿的产品排入队列；同一页面会话内同一周期、产品、指纹只尝试一次。
3. 顺序生成，避免打开报告时同时向模型发送所有产品请求。每个产品成功后立即保存既有报告草稿表，并更新该产品的展示；报告其他部分可继续使用。
4. 生成过程中用户输入的人工结论或举措不得被异步结果覆盖。周期切换或证据改变后，旧请求结果不得写入新报告。
5. 未配置模型、生成失败或保存失败时保留规则稿，展示简短状态与失败产品；不写入不完整稿件。页面无手动 AI 生成入口。

## 模型响应

生成请求优先使用 JSON 输出约束；上游不支持时沿用代理已有的兼容重试。报告生成器在解析前检查 `finish_reason`，区分输出截断与格式错误。仅对这两类可恢复错误做一次加大输出预算的重试，逐阶段校验所需字段。最终失败时只给用户简短错误，不把包含客户反馈的模型原文放进提示。

## 取舍与验证

首版在已登录编辑者的报告页执行队列，复用现有草稿存储和证据指纹，避免迁移整套报告取数到服务端。不同浏览器同时打开同一报告仍可能重复调用模型；已保存稿按指纹复用，后续若并发成本明显再增加服务端任务锁。

验证覆盖月报与季报、已有稿命中与证据变化、普通查看者、异步期间人工编辑、周期切换、模型截断与非法 JSON、重试失败回退。运行受影响 Vitest 子集、构建，并在可用环境下目检报告状态。
