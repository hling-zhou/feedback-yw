全局规则
邮件粒度 一封邮件，只含有待办的产品段落（无待办产品不列入，其负责人不收邮件）
收件人 仅有待办产品的五角色负责人并集（产品经理 / 设计师 / 运维三线 / 运营 / 测试，来自 product_catalog owners 配置）。产品本期无待办 - 该产品负责人不收邮件
产品内关注 各产品段落标题旁标注需关注的角色（规则引擎判定），不裁剪收件人
正文形式 A+B 组合：正文内联 HTML 简短摘要（每产品一行汇总：产品名-待办总数-需关注角色），附件 .html 含完整分产品详情（产品 Tab 切换）。邮件客户端剥除 JS - 正文无法做 Tab，附件在浏览器打开体验 = 平台原生
数据量 每类最多 50 条 + "更多详见平台"提示
LLM 每产品调 1 次 LLM：生成产品概述段落 + 趋势洞察（不做行动建议、不裁剪收件人）。失败则标记"LLM分析不可用"，规则数据正常渲染
触发方式 第一期手动触发（预览-确认-发送），第二期用 automation 定时。入口：右下角悬浮按钮（FloatButton），仅 admin 可见，临时放置
洞察周期 可选：投诉工单 / 用后即评-补充的回访结果待评估 / 客户体验类分析会会后待办 按周期过滤；用后即评-产品部溯源 / 未完成举措 不受限（持续待办全纳入）
SMTP 通道 DATA_SOURCE_TYPES 新增 'reminder' 类型，管理员在设置页为提醒邮件配置独立 SMTP 通道（可与用后即评复用同一 host/账号，但 dataSourceType 不同，发件人地址可区分如 reminder@cmss.chinamobile.com）。发送时调 getMailChannelByDataSource('reminder')
入口与权限 右下角悬浮按钮（antd FloatButton），仅 admin 角色可见。点击后弹窗：选洞察周期 → 预览（产品/收件人/摘要） → 确认发送。临时放置，后续视使用情况再定正式入口位置
请求场景 9 类（咨询工单分布用）：报障与排错 - 资源操作申请 - 操作指导 - 进度催办与协同 - 产品信息咨询 - 方案咨询与设计 - 费用与账务 - 信息查询 - 服务申诉与投诉
